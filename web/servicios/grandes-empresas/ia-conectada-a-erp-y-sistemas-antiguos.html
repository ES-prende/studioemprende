Grandes empresas

IA conectada a ERP y sistemas antiguos sin reemplazar lo que funciona

Conectar la IA a un ERP o a un sistema antiguo es posible aunque no tenga una API moderna: se elige la vía que el sistema admite y se limita lo que el agente puede tocar.

Quiero esto en mi negocioVer grandes empresas

Respuesta corta

Para conectar un agente de IA a un ERP o a un sistema heredado se usa la vía que ese sistema permita: su API si la tiene, una réplica de la base de datos, el intercambio de ficheros o, como último recurso, la automatización de pantallas. El agente empieza con permisos de solo lectura y cada escritura pasa por reglas y aprobación.

¿Por dónde se conecta según el sistema?

Se usa la API del ERP si existe y está documentada; si no, una réplica de la base de datos, ficheros de intercambio programados o, como último recurso, automatizar las pantallas con controles adicionales.

API del ERP

La opción más limpia cuando el fabricante la ofrece y está documentada.

Réplica de base de datos

Consultas sobre una copia, sin cargar el sistema de producción.

Ficheros de intercambio

Exportaciones e importaciones programadas en CSV, XML u otros formatos que el sistema ya genere.

Automatización de pantallas

Para aplicaciones sin otra salida, con más mantenimiento y controles adicionales.

¿Cómo se controla lo que hace la IA?

La IA empieza con permisos de solo lectura, cualquier acción pasa por una capa propia que valida los datos antes del ERP y cada consulta, propuesta y aprobación queda registrada para auditoría.

Solo lectura al principio

El agente consulta y propone; no escribe nada hasta validar su comportamiento.

Capa intermedia

Las acciones pasan por un servicio propio que valida los datos antes de llegar al ERP.

Registro de cada operación

Qué consultó, qué propuso y quién lo aprobó, para auditoría interna.

¿Qué tareas puede hacer la IA sobre un ERP?

Conectada al ERP, la IA puede consultar datos, preparar operaciones para que una persona las apruebe y avisar de situaciones que nadie está mirando. Algunos ejemplos concretos:

  • Responder a comerciales sobre el estado de un pedido o el stock disponible sin que entren en el ERP.
  • Leer pedidos que llegan por correo en PDF y dejarlos como borrador en el sistema.
  • Comparar facturas de proveedores con los albaranes recibidos y marcar diferencias.
  • Generar resúmenes de ventas o de cobros pendientes en lenguaje normal para dirección.
  • Avisar cuando un cliente supera su límite de riesgo o un artículo baja de mínimos.

Si en vuestra organización hay dudas sobre qué hace un ERP y qué no, el artículo que explica para qué sirve un ERP sirve de base común para negocio y sistemas.

Comparativa de las vías de conexión

Elegir la vía de conexión es una decisión entre limpieza técnica, coste y riesgo. Esta tabla compara las cuatro opciones:

VíaVentajaLimitaciónMantenimiento
API del fabricanteControlada y documentadaNo todos los ERP la tienen o la licencian aparteBajo
Réplica de base de datosNo toca producciónSolo lectura; los datos van con algo de retrasoMedio
Ficheros de intercambioFunciona con casi cualquier sistemaNo es en tiempo realMedio
Automatización de pantallasÚnica salida en algunos sistemas cerradosSe rompe si cambia la pantallaAlto

Cuando hay que unir varios programas además del ERP, las integraciones por API resuelven la parte de conexión entre sistemas.

Pasos para conectar un agente a un sistema heredado

Con un sistema antiguo, el orden de trabajo importa más que la tecnología elegida. Los pasos habituales son estos:

  1. Reunión con quien mantiene el sistema para conocer sus límites, horarios de carga y cambios previstos.
  2. Elección de la vía de conexión y prueba en un entorno que no sea producción.
  3. Definición de la capa intermedia: qué datos se leen, qué operaciones se permiten y con qué validaciones.
  4. Agente en modo consulta durante unas semanas, con revisión de respuestas.
  5. Activación gradual de escrituras, una operación cada vez, con aprobación humana.

Si el sistema está tan desactualizado que ya no tiene quien lo mantenga, conviene valorar en paralelo un rescate de software antiguo, aunque la IA se conecte primero.

Preguntas frecuentes

¿Se puede usar IA con un AS/400 o un programa en Cobol?

En muchos casos sí, a través de ficheros, bases de datos o emulación de pantalla; se estudia cada sistema antes de comprometer plazos.

¿La conexión de la IA afecta al rendimiento del ERP?

Se diseña para no hacerlo: consultas sobre réplicas, horarios de baja carga y límites de peticiones.

¿Tenemos que actualizar el ERP antes de añadir IA?

No necesariamente: la idea es aprovechar lo que funciona, conectar la IA por encima y dejar la renovación para cuando tenga sentido.

¿Qué permisos necesita el agente dentro del ERP?

Los mínimos para el caso de uso. Se crea un usuario de servicio propio, nunca el de una persona, con acceso de lectura a las tablas necesarias y, si hace falta escribir, solo a operaciones concretas. Así se pueden auditar y retirar sus permisos sin afectar a nadie.

¿Se puede conectar la IA a un ERP instalado en nuestros servidores?

Sí. La conexión se hace desde dentro de vuestra red o mediante un canal seguro autorizado por sistemas. Si además el modelo de IA debe ejecutarse en local, se puede montar en servidor propio para que ningún dato salga de la infraestructura de la empresa.

¿Qué pasa si el fabricante del ERP cambia su API?

La capa intermedia aísla al agente de esos cambios: si la API cambia, se adapta esa capa y el agente sigue igual. Además, el mantenimiento incluye revisar las notas de versión del fabricante y probar la conexión antes de cada actualización importante.
