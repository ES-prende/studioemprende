Velocidad y Core Web Vitals: que tu web cargue antes de que se vayan

La velocidad de una web y sus Core Web Vitals miden cuánto tarda en verse, en responder y si se mueve mientras carga. Son señales que Google tiene en cuenta y, sobre todo, lo que decide si el visitante espera o se va.

Quiero esto en mi negocioVer webs

Respuesta corta

Las Core Web Vitals son tres métricas de Google sobre la experiencia real de los usuarios: LCP, el tiempo hasta que se ve el contenido principal (bueno por debajo de 2,5 segundos); INP, lo que tarda la página en reaccionar a un toque o clic (bueno por debajo de 200 milisegundos); y CLS, cuánto se desplaza el contenido mientras carga (bueno por debajo de 0,1).

¿Qué suele hacer lenta una web?

Imágenes sin optimizar

Fotos de varios megas servidas a un móvil; se convierten a formatos modernos y al tamaño justo.

Plugins y scripts de más

Chats, píxeles, sliders y plantillas pesadas que cargan código en todas las páginas.

Alojamiento y caché

Un servidor lento o sin caché ni CDN añade segundos antes de empezar.

Fuentes y anuncios que empujan

Elementos que aparecen tarde y desplazan el texto, lo que empeora el CLS.

¿Cómo trabajamos?

Partimos de los datos de campo de tus visitantes reales, no solo de una prueba de laboratorio, y priorizamos las páginas que más tráfico y contactos traen. Después de corregir, medimos de nuevo y dejamos una vigilancia para que una actualización o un plugin nuevo no vuelva a estropearlo.

Cómo leer el informe de PageSpeed sin perderte

El informe de PageSpeed Insights tiene dos partes y la que importa para Google es la primera: los datos de campo de usuarios reales. Conviene leerlo así:

  • Datos de campo: medidas de visitantes reales de Chrome en los últimos 28 días. Google evalúa el percentil 75, es decir, la experiencia del 75 % de las visitas.
  • Datos de laboratorio: una simulación en un móvil de gama media. Sirve para encontrar causas, pero su nota puede variar de una prueba a otra.
  • Oportunidades y diagnósticos: la lista de causas concretas, como imágenes demasiado grandes o código que bloquea la carga.

Si tu web tiene pocas visitas, puede no haber datos de campo; entonces se trabaja con el laboratorio y con la medición propia.

Arreglos habituales para LCP, INP y CLS

Orden de trabajo en una web lenta

  1. Identificar las plantillas con más tráfico: portada, páginas de servicio, fichas de producto.
  2. Medir cada plantilla en móvil y anotar la métrica que falla.
  3. Resolver primero lo que afecta a todas las páginas, como el alojamiento, la caché o un plugin global.
  4. Después, los problemas de cada plantilla.
  5. Medir de nuevo y esperar a que los datos de campo se actualicen.
  6. Dejar vigilancia para detectar si algo vuelve a empeorar.

Esa vigilancia puede ir dentro del mantenimiento web mensual o de la monitorización continua de la web.

Ejemplo: tienda de recambios con fichas lentas

Imagina una tienda de recambios cuyas fichas de producto tardan en mostrarse en el móvil. El análisis muestra tres causas: fotos del fabricante sin optimizar, un widget de reseñas que se carga entero al abrir la página y un buscador de compatibilidad que bloquea el resto del código. Optimizando imágenes, cargando las reseñas al llegar a ellas y diferiendo el buscador, las fichas pasan a mostrar el producto casi al instante. Si la plataforma impide estos cambios, la alternativa es la migración a una base más ligera.

Preguntas frecuentes

¿Cómo sé si mi web pasa las Core Web Vitals?

En Search Console, en el informe de experiencia, o en PageSpeed Insights con la URL de tu web; te dirá si pasa con datos de usuarios reales.

¿Influye la velocidad de la web en el posicionamiento en Google?

Es una de las señales de experiencia que Google tiene en cuenta; no sustituye al contenido, pero con contenidos parecidos ayuda, y sobre todo reduce abandonos.

¿Se puede acelerar una web de WordPress sin rehacerla?

Normalmente sí: optimizando imágenes, quitando plugins, configurando caché y mejorando el alojamiento.

¿Por qué mi web va rápida en el ordenador y lenta en el móvil?

El móvil tiene menos potencia y a menudo peor conexión, y la mayoría de pruebas se hacen simulando un móvil de gama media. Imágenes grandes, scripts pesados y plantillas complejas se notan mucho más ahí. Como la mayoría de visitas llegan desde el móvil, es la versión que hay que optimizar primero.

¿Cuánto tarda Google en reflejar las mejoras de velocidad?

Los datos de campo de Google se calculan sobre los últimos 28 días de visitas, así que las mejoras se reflejan de forma progresiva durante unas cuatro semanas. La prueba de laboratorio muestra el cambio al momento y sirve para confirmar que el arreglo funciona mientras se actualizan los datos reales.

¿Una web pequeña necesita CDN?

No siempre. Si tus visitantes están en España y el alojamiento está bien configurado, la diferencia puede ser pequeña. Una CDN ayuda cuando hay visitas desde lejos, muchas imágenes o picos de tráfico, y además añade protección. Muchas se pueden activar con poco coste y sin tocar la web.
